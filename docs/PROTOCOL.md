# 协议与实现说明

本文件描述当前代码的行为，不能替代厂家对其他固件的协议说明。PiPER 使用 SocketCAN 标准帧、1 Mbps、8 字节载荷；下列多字节数值按 big-endian 编码。来源为 [piper_sdk protocol v2](https://github.com/agilexrobotics/piper_sdk) 与厂家示例。

## 正常控制帧

| CAN ID | 用途 | 当前桥接的编码 |
| --- | --- | --- |
| 0x151 | 控制模式 | CAN=1、MOVE J=1、速度百分比；joint 模式标志0，JS servo 标志0xAD |
| 0x155 | J1/J2 目标 | 两个 int32，每单位0.001° |
| 0x156 | J3/J4 目标 | 两个 int32，每单位0.001° |
| 0x157 | J5/J6 目标 | 两个 int32，每单位0.001° |
| 0x159 | 夹爪 | 开口 int32（0.001mm）、力矩 uint16（0.001N·m）、使能字节1、末字节0 |
| 0x150 | 模式准备/停止 | 首字节1快速停止，2为厂家复位；复位只出现在显式准备流程 |
| 0x471 | 关节使能 | 显式准备流程使用电机选择7、使能2 |

正常 joint 循环每次发送模式帧及三个关节帧；开启夹爪时再发一帧。默认100Hz约500帧/秒，不含设备反馈。JS模式首次会先预装关节目标再切入模式，避免用旧目标进入快速跟随。本代码不发送每电机MIT力矩控制帧。

0x472/0x473可用于厂家定义的限位参数查询，但普通预览和`--diagnose-can`不会发送这些查询；不要把这两个零发送模式误解为主动扫描设备。

## 接收反馈

| CAN ID | 内容 | 是否用于当前检查 |
| --- | --- | --- |
| 0x2A1 | 控制模式、状态、运动模式、示教状态、错误位 | 必要 |
| 0x2A5–0x2A7 | 六关节角度，每单位0.001° | 必要 |
| 0x261–0x266 | 六电机低速状态，含使能与故障位 | 必要 |
| 0x2A8 | 夹爪开口、力矩、使能与故障位 | 控制夹爪时必要 |

记录接收时的 monotonic 时间。必要反馈超过250ms未更新，运行立即停止；启动可等待最多2秒形成完整反馈。反馈角度不会因超出发送限位而被篡改，实际关节反馈与合法命令目标分别处理。

## 线程和状态

1. 接收线程持续读取CAN，将反馈放入受锁保护的快照。
2. 主线程读取SO-101、读取PiPER快照、处理键盘，再生成并发送目标。
3. 接收线程在LIVE期间独立检查反馈和主线程心跳，避免主控串口读取卡住时仍无限持有“运行中”的状态。
4. 每次成功完整发送后才将目标加入跟随历史；发送失败不能假装该目标已执行。
5. 遇错锁定停止，正常恢复通知不会清除锁定。新进程重新接管必须使用新鲜姿态和现场ARM。
6. 异常先停止，再读取接口诊断及写入故障文件；诊断IO不阻挡首个停止动作。

`device_locks`阻止本项目多个实例抢同一个CAN；读取leader时也锁定串口并用fuser检测占用。它不是其他所有机器人软件的全局互斥机制，因此仍会监测其他端发出的相关控制帧。

## 模式准备为何独立

`--prepare-can`不读leader；若CAN/MOVE J已健康且六关节已使能，零发送退出。否则在现场ARM后：

1. 检查厂家复位支撑姿态，快速停止。
2. 复位并留出1秒厂家恢复窗口，等待六关节失能。
3. 在失能状态切换待机和CAN/MOVE J。
4. 重新读取姿态，将保持目标裁剪到合法指令范围，并限制与实测差不超过5°。
5. 预装三个关节目标帧，再使能关节并验证状态。

仅记录在源码中的复位恢复窗口可以暂时容忍缺帧或纯通信状态位；正常运行没有相同宽限。准备失败不会循环复位。复位有卸力风险，必须支撑，不等于自动回零或无碰撞路径规划。

## CAN错误与恢复通知

SocketCAN的错误标志是`0x20000000`，低位掩码才是错误类别。例子：

| ID / 载荷 | 当前解释 |
| --- | --- |
| 0x20000024 / 0000000000000800 | CONTROLLER + NO_ACK，真实错误，停止 |
| 0x20000004 / 0000000000000000，驱动gs_usb | 已知ERROR-ACTIVE通知，继续 |
| 0x20000004 / 0000000000005f00，驱动gs_usb | 已知旧固件带低于96计数字节的ERROR-ACTIVE通知，继续 |
| 纯0x20000004但带warning/passive/overflow位 | 停止 |
| 纯0x20000004但保留字节非零、计数字节≥96 | 不套用已知恢复规则，停止 |
| 相同恢复载荷但其他/未知驱动 | 不套用gs_usb特例 |

[Linux v6.8 gs_update_state](https://github.com/torvalds/linux/blob/v6.8/drivers/net/can/usb/gs_usb.c#L460) 将无warning/passive位的CONTROLLER通知设为ERROR_ACTIVE。[candleLight v2.0](https://github.com/candle-usb/candleLight_fw/blob/v2.0/src/can.c#L262) 在data[6:8]放计数但不置CAN_ERR_CNT，恢复时因此不一定全零。代码依据驱动、ID、完整载荷形态和计数阈值识别，不能只判断“包含CONTROLLER就是错误”。

没有标准CAN_ERR_CNT标志时，结构化的标准计数字段保持null，原始字节完整记录。不能把null读成零；也不能因为后续恢复就把之前真实NO_ACK改为成功。原始错误位定义见[Linux can/error.h](https://github.com/torvalds/linux/blob/v6.8/include/uapi/linux/can/error.h)。
