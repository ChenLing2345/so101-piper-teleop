# 验证范围与已知限制

## 发布版与原部署的区别

运动逻辑、CAN编码、相对锚定、腕部range映射、夹爪控制和停止保护来自原部署桥接。发布版新增可移植安装、可配置leader ID/端口、LeRobot默认标定路径、用户可写的故障目录及统一CLI信号处理。不会替换原部署文件或在开源整理时驱动机械臂。

原部署使用Linux内核6.8、Python3.10、原版SO-101、gs_usb/candleLight和一台PiPER（反馈固件S-V1.8-4）。原checkout报告LeRobot0.4.3但尚用旧so101_leader模块；PyPI同版本已合并为so_leader。发布版针对这两个实际遇到的布局做了适配，并按上游CLI顺序先初始化processor，避免PyPI版本的循环导入，不能把版本字符串相同等同于源码相同。

原始部署有126项离线回归测试；发布版保留它们并增加打包/配置验证。测试使用模拟反馈或Unix socket pair，不会打开硬件。发布整理时：隔离基础环境129项通过、1项可选LeRobot适配测试跳过；加载PyPI 0.4.3源码与已安装依赖后130项全部通过；原部署LeRobot布局的4项发布配置/适配测试也通过。wheel和源码分发构建成功。CI基础环境会跳过未安装的可选适配测试，实际结果以工作流输出为准。

发布整理过程中会验证LeRobot读者的构造、标定加载与角度范围计算，但不主动打开电机连接；不能把这种适配验证称为新版本实机验收。

## 已知未解决项

- 曾在持续遥操后发生真实NO_ACK，随后暂时全反馈缺失。具体线材、供电、转接器或控制器瞬态原因尚未定位。
- 后续短时通信正常，不能证明长期不会再次出现NO_ACK；遇到真实错误仍会停止并保存诊断。
- 固定J4意味着不能完整控制PiPER六个旋转自由度，两个不同结构机械臂也不保证相同TCP位置或离桌高度。
- 默认方向来自测试装配；移植后应小幅逐轴核实。
- 腕部range是分段线性映射。锚点附近两侧斜率可以不同，近端点重新锚定后也可能更灵敏。
- 60°/s和240°/s²是软件目标上限，不是全负载下的设备性能承诺。
- 固定命令限位属于测试设备配置，尤其J6±180°不能直接用于所有PiPER型号。
- 不含碰撞检测、机械急停装置、相机同步、数据集记录、示教回放或策略推理。
- 没有关闭或屏蔽LED的功能；普通CAN模式的示教灯表现由设备固件决定。

本仓库发布功能代码与汇总结果，不上传私人现场照片、原始设备日志、序列号或标定文件。
